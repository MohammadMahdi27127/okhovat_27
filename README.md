# اخوت | نسخهٔ متصل FastAPI
فرانت‌اند فارسی از همان دامنه‌ای سرو می‌شود که API را اجرا می‌کند. ورود، نشست هفت‌روزه، گزارش رشد و انتشار اختیاری خلاصهٔ عمومی آن، پست و پیوست، نظر و پسند، پیشنهاد به مربی، پیام و آرشیو مربی، امتیاز حلقه و کارگروه، برنامه و کتاب عضو و آمار دستیار در این نسخه مسیر سروری دارند. راهنمای اولین بازدید و تم دستگاه در مرورگر می‌مانند.

## اجرای محلی با PostgreSQL
۱. Docker Compose و Python 3 را در دستگاه داشته باشید.
۲. در پوشهٔ حاوی compose.yaml این دستورها را اجرا کنید (در ویندوز می‌توانید برای دستور نخست از py استفاده کنید):
```sh
python3 setup_env.py
docker compose up --build -d
```
۳. http://localhost:8080/login/ را باز کنید. رمزهای تازه در فایل .env کنار compose.yaml هستند. کد 27127 با MEMBER_PASSWORD و کد 90001 با COACH_PASSWORD وارد می‌شود. این متغیرها حساب را در اولین اجرا ایجاد می‌کنند. تغییر آن‌ها رمز حساب موجود را بازنویسی نمی‌کند. .env را در گیت منتشر نکنید.
۴. با عضو گزارش ثبت کنید. در یک پنجرهٔ خصوصی با حساب مربی وارد شوید، «پنل نظارتی ← نظرات فردی» را باز کنید و عضو را انتخاب کنید. به همان فرد پیام بدهید و سپس در حساب عضو صفحهٔ پروفایل را باز کنید.
۵. وضعیت سرویس‌ها با docker compose ps و لاگ برنامه با docker compose logs web نمایش داده می‌شود. برای توقف از docker compose down استفاده کنید. داده‌ها و فایل‌های پیوست در volume می‌مانند.

## نصب روی سرور
Compose یک PostgreSQL مستقل و جداول با پیشوند ok_ می‌سازد. برای سرور PostgreSQL موجود می‌توانید DATABASE_URL سرویس web را به دیتابیس مقصد تغییر دهید. جداول قدیمی Django و گزارش‌های آزمایشی مرورگر به‌طور خودکار وارد نمی‌شوند. برای نگاشت داده‌های قبلی باید ساختار واقعی و شناسه‌های حساب‌ها تطبیق داده شود. فایل‌های django-integration، src و server/django_assistant برای مرجع نسخهٔ قبلی هستند؛ برنامهٔ اجرایی این نسخه api/main.py و dist است.
HTTPS را در reverse proxy به 127.0.0.1:8080 متصل کنید و COOKIE_SECURE=1 در .env تنظیم کنید. از volume دیتابیس و volume فایل‌ها پشتیبان بگیرید. ساخت کاربر اضافی:
```sh
docker compose exec web python -m api.accounts --code 27128 --name "عضو دوم" --role member --ring "سلمان" --team "آموزش"
```

## API و تست
مسیر /docs فهرست تعاملی API را نمایش می‌دهد. برای درخواست‌های نوشتن، کلاینت هدر X-Okhovat با مقدار 1 را همراه کوکی HttpOnly می‌فرستد. دسترسی مربی، هویت نویسنده و گیرندگان پیام در سرور تعیین می‌شوند. تاریخ میلادی و نمایش شمسی گزارش هر دو ثبت می‌شوند. اطلاعات شخصی API در مرورگر کش نمی‌شود.
- POST /api/login و /api/logout، GET /api/session و /api/state
- PUT /api/growth، POST /api/posts، POST /api/posts/{id}/comments و PUT /api/posts/{id}/votes/{kind}
- POST /api/messages، POST /api/messages/read و PUT /api/grades/{kind}
- PUT /api/profile/status و /api/profile/avatar، POST /api/files/{purpose}
- POST /api/assistant/chat/ برای آمار خود و حلقه؛ در صورت داشتن Ollama، نام مدل نصب‌شده و نشانی سرویس را با ASSISTANT_OLLAMA_MODEL و ASSISTANT_OLLAMA_URL تنظیم کنید.

تست خودکار در پوشهٔ پروژه با Python 3.12:
```sh
pip install -r requirements.txt httpx
python -m unittest api.test_integration
```
تست از SQLite موقت و نشست‌های جدا استفاده می‌کند. پیکربندی Compose از PostgreSQL استفاده می‌کند. اجرای python -m http.server به تنهایی برای این نسخه کافی نیست.

## Redis، امنیت و ظرفیت
با همان نام پروژهٔ Compose و فایل .env قبلی، از دستورهای زیر استفاده کنید تا volumeهای قبلی دوباره متصل شوند. setup_env.py رمز حساب‌های قبلی را نگه می‌دارد و کلیدهای جدید را اضافه می‌کند.
```sh
python3 setup_env.py
docker compose up --build -d
```
در ویندوز دستور اول را با py اجرا کنید. مرحلهٔ migrate پیش از اجرای وب، جداول افزایشی و حساب محدود PostgreSQL را آماده می‌کند. ساختار اصلی جداول حذف یا بازنویسی نمی‌شود. اتصال Redis فقط در شبکهٔ داخلی Docker است.

- **کش** برای پاسخ شخصی /api/state در سرور است. کلید به هویت، نقش، حلقه، کارگروه و نسخهٔ داده وابسته است. TTL برابر ۹۰۰ ثانیه است. تغییر داده از طریق API نسخه را در همان تراکنش عوض می‌کند. خروج از حساب بلافاصله دسترسی را می‌بندد. نشست ورود در PostgreSQL با انقضای ثابت هفت روزه باقی می‌ماند. اسکریپت، سبک و تصویر عمومی برای مرورگر حداکثر ۱۵ دقیقه کش می‌شوند. پاسخ‌های خصوصی API هدر no-store دارند. تم و وضعیت اتمام راهنما همچنان متعلق به مرورگرند.
- **خرابی سرویس** در صورت خطای Redis، وب برای پنج ثانیه دوباره اتصال کش را امتحان نمی‌کند و داده را از دیتابیس می‌خواند. خطای عملیاتی دیتابیس پاسخ ۵۰۳ با Retry-After دارد. قطع دیتابیس دسترسی به دادهٔ خصوصی کش‌شده را هم می‌بندد.
- **بار** سقف هر فرایند ۳۲ درخواست فعال API، سه محاسبهٔ هم‌زمان رمز، سه ساخت هم‌زمان پاسخ state، سه آپلود و سه درخواست مدل است. حداکثر فایل ۱۰ MiB است؛ حجم بدنه و مهلت خواندن آن پیش از تجزیه کنترل می‌شوند. سهمیهٔ پیش‌فرض فایل‌های جدید هر کاربر ۲۵۶ MiB است. مصرف قدیمی پیش از ارتقا در این سهمیه وارد نشده است. Redis حداکثر ۶۴ MiB دادهٔ کش و سیاست allkeys-lru دارد.
- **محدودیت استقرار** شمارنده‌های نرخ در فرایند وب قرار دارند؛ تنظیمات پیش‌فرض یک کارگر اجرا می‌کند. برای چند نمونهٔ مستقل باید سقف سراسری در reverse proxy تنظیم شود. در پشت پراکسی فقط IP پراکسی تحت کنترل خود را برای forwarded headers مورد اعتماد قرار دهید. فشار واقعی و ظرفیت مورد نیاز به سرور شما بستگی دارد.
- **حد رشد داده** درخواست تجمیعی state سقف ۳۰٬۰۰۰ ردیف پردازش‌شده و بودجهٔ ۸ MiB داده دارد. اگر از بودجه عبور کند، پاسخ ۵۰۳ می‌دهد. برای جامعه‌ای که مرتب به این سقف می‌رسد، فید و گزارش‌ها به API صفحه‌بندی‌شده نیاز دارند.
- **امنیت عملیاتی** برای دامنهٔ عمومی HTTPS و COOKIE_SECURE=1 را فعال کنید. رخدادهای رد درخواست شناسه دارند. لاگ چرخشی Docker به ۳ فایل ۱۰ MiB محدود است. اسکریپت‌های خارجی رابط و برخی رویدادهای inline فعلی برای سازگاری مجازند. نسخهٔ حاضر ممیزی مستقل، اسکن زندهٔ وابستگی‌ها یا آزمون ظرفیت روی سرور مقصد را طی نکرده است.
- **تست** در محیط توسعه با httpx نصب‌شده، `python -m unittest api.test_integration api.test_hardening` را اجرا کنید. این آزمون‌ها از SQLite موقت و جایگزین Redis استفاده می‌کنند. برای بررسی Compose واقعی، پس از ورود صفحهٔ پست‌ها را باز کنید و وضعیت سرویس‌ها را با `docker compose ps` ببینید. نشست هفت‌روزه پس از توقف و راه‌اندازی مجدد cache باقی می‌ماند.

بررسی اتصال واقعی PostgreSQL و Redis پس از راه‌اندازی:
```sh
docker compose exec web python -m api.check_redis
```
این فرمان نقش سرویس وب و جدول نسخهٔ داده را می‌خواند و یک کلید تصادفی Redis را با TTL بررسی و پاک می‌کند.

## حضور شیت پذیرش
در هر ورود موفق عضو، FastAPI تب پذیرش با شناسهٔ 643360414 را می‌خواند، کد گروهی را در ستون اول تطبیق می‌دهد و در پروفایل، حضور عضو و سایر ردیف‌های همان حلقه را نشان می‌دهد. نتیجهٔ این بررسی به نشست ورود تعلق دارد. باز کردن پروفایل، شیت را دوباره دانلود نمی‌کند. قطع شیت مانع ورود نیست.

برای شیتی که سرور اجازهٔ خواندن آن را دارد، خروجی CSV استفاده می‌شود. برای شیت خصوصی، حساب سرویس Google با دسترسی Viewer به همان فایل و Google Sheets API فعال لازم است. کلید JSON را فقط به‌صورت فایل read-only در کانتینر web مونت کنید و GOOGLE_APPLICATION_CREDENTIALS را در همان سرویس به مسیر آن فایل تنظیم کنید؛ در این حالت درخواست فقط برای همان تب به API گوگل ارسال می‌شود.

## مدیریت پست و ثبت عضو
پس از اجرای مهاجرت Compose، مالک سرور یک حساب موجود را برای مدیریت انتخاب می‌کند:
```sh
docker compose exec web python -m api.grant_admin YOUR_GROUP_CODE
```
به‌جای YOUR_GROUP_CODE کد حساب خودتان را بنویسید. این دستور نقش اصلی حساب را حفظ می‌کند. صفحه را تازه کنید. در «پست‌ها ← مدیریت پست» حذف را تأیید کنید. حذف مدیریتی ثبت می‌شود؛ متن و پیوست پست حذف‌شده در فید و API عمومی اعضا در دسترس نخواهد بود. اگر پست خلاصهٔ رشد باشد، اصل گزارش خصوصی باقی می‌ماند. برای ثبت حساب عضو عادی از «پروفایل ← ثبت عضو جدید» استفاده کنید. کد تکراری باعث تغییر حساب موجود نمی‌شود.

گزینهٔ انتشار گزارش رشد برای گزارش جدید خاموش است. با برداشتن تیک و ذخیرهٔ مجدد، پست خلاصه و تعاملات آن حذف می‌شوند و اصل گزارش باقی می‌ماند.
